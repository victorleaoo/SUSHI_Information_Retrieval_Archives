# Phase 1: Query Expansion Implementation Documentation

This document describes the files, modules, and scripts implemented to execute **Phase 1: Query Expansion** of the SUSHI experiments.

## 1. Newly Created Files & Directory Structure

The following files were created based on the instructions in `experiments.md` to support indexing, querying, and retrieving archival documents using the Groq API and several retrieval models.

```text
src/
├── run_phase1_allf.py             # Main execution script for all Phase 1 experiments
├── utils/
│   ├── llm_client.py              # LLM API wrapper for Groq with SHA256-based disk caching
│   ├── field_resolver.py          # resolve_folder_fields() — maps JSON fields to prompt variables
│   └── ecf_utils.py               # ECF loading + training doc extraction per folder
├── query_expansion/
│   ├── generate_hyde.py           # LLM → Q1 (HyDE) for all 45 topics
│   ├── generate_keywords.py       # LLM → Q2 (Keywords) for all 45 topics
│   ├── generate_emb_text.py       # LLM → Q3 (Embedding Text) for all 45 topics
│   ├── generate_reformulations.py # LLM → Q4 (Reformulations) for all 45 topics
│   └── combine_queries.py         # Combines saved outputs into Q12, Q13, Q14, and QALL
└── retrieval/
    ├── allf_index.py              # Builds folder-level index for F1–F5 configurations
    └── allf_retrieval.py          # Runs retrieval using indices and performs Reciprocal Rank Fusion (RRF)
```

## 2. Module Details

### `src/utils/llm_client.py`
A robust LLM client wrapper configured to use **Groq** by default. It takes a prompt and system prompt, calculates a SHA256 hash to act as a cache key, and saves the output to `data/llm_cache/`. This ensures the 180 LLM calls for query generation are only executed once, saving time and API costs. It includes a retry mechanism for rate limits.

### `src/utils/field_resolver.py`
Contains `resolve_folder_fields(folder)` which handles the complex mapping logic described in `experiments.md`. It normalizes fields like `label`, `label_parent_expanded`, `main_title`, `snc`, etc., and handles edge cases such as missing end dates and "Unknown" SNC codes.

### `src/utils/ecf_utils.py`
Helper functions (`load_ecf`, `get_training_docs_per_folder`) used to parse ECF (Experiment Configuration File) JSON files and map folder IDs to training document IDs.

### `src/query_expansion/generate_*.py`
Four scripts that use the `LLMClient` to process the 45 evaluation topics (from `src/data_creation/topics_output.txt`) and generate synthetic queries:
- **Q1 (HyDE):** Generates synthetic folder labels.
- **Q2 (Keywords):** Generates a comprehensive list of specific terms, entities, and events.
- **Q3 (Embedding Text):** Generates a 150-200 word descriptive paragraph optimized for dense vector retrieval.
- **Q4 (Reformulations):** Generates 4 different search queries from different angles.

### `src/query_expansion/combine_queries.py`
Reads the JSON files generated by the above scripts and combines them (by concatenating their strings) into composite queries:
- **Q12:** Q1 + Q2
- **Q13:** Q1 + Q3
- **Q14:** Q1 + Q4
- **QALL:** Q1 + Q2 + Q3 + Q4

### `src/retrieval/allf_index.py`
Contains logic for assembling folder index text based on configurations F1 through F5:
- **F1:** Folder Label only
- **F2:** Folder Label + Parent Expanded SNC
- **F3:** Folder Label + Scope Note
- **F4:** Folder Label + Parent Expanded SNC + Scope Note
- **F5:** Folder Label + Parent Expanded SNC + Scope Note + Main Title

It initializes and trains the appropriate model (`BM25Model`, `EmbeddingsModel`, `ColBERTModel`) using the assembled text.

### `src/retrieval/allf_retrieval.py`
Executes searches across the trained models for each topic. Critically, it handles the ensemble logic:
- If a single base model (B, E, or C) is passed, it returns its results directly.
- If multiple models are passed (BC, BE, CE, BCE), it performs **Weighted Reciprocal Rank Fusion (WRRF)** using the predefined weights (`bm25`: 1.0, `colbert`: 0.65, `embeddings`: 0.65) and an RRF constant `k=60`.

### `src/run_phase1_allf.py`
The master orchestrator script for Phase 1. When executed, it performs the following:
1. **Prepare Queries:** Calls the LLM query generation scripts to create Q1-Q4 and combines them. (Skipped automatically if JSON files already exist).
2. **Set 1A (Normal Queries):** Iterates over configs `F1`-`F5` and models `B, E, C, BCE, BC, BE, CE`. Trains the indices once per config and queries using the original Topic Description (Q0). Evaluates results using `Evaluator` and determines the best config (`F_best`) for each base model type.
3. **Set 1B (Expanded Queries):** Using the `F_best` config found for each model, runs the expanded queries (Q1, Q2, Q3, Q4, Q12, Q13, Q14, QALL) based on the combinations specified in `experiments.md` (33 total runs).

## 3. How to Run Phase 1

### Prerequisites
Before running, you must set the `GROQ_API_KEY` environment variable. The scripts default to using the Groq API (using the `llama3-70b-8192` model, or whichever Groq model you configure).

```bash
export GROQ_API_KEY="your_api_key_here"
```

Also, ensure the required Python packages are installed (as per the main project requirements).

### Execution

To run the entire Phase 1 pipeline automatically, simply execute the main script from the root directory:

```bash
python src/run_phase1_allf.py
```

### What happens when you run it:
1. You will see progress in the console for generating LLM queries (this uses the Groq API and creates files in `data/` and `data/llm_cache/`).
2. The script will train indices for F1-F5 (this may take some time depending on ColBERT/Embeddings initialization).
3. The script will perform the 35 runs (5 configs × 7 models) for **Set 1A** and print out the best config (F_best) for B, E, C, and BCE.
4. The script will run the 33 runs for **Set 1B** using the dynamically identified best configurations.
5. All results (nDCG@5, MAP, etc.) will be saved to `all_runs/Phase1_{RunID}_{Config}_{Model}/` along with the TREC format `.tsv` files.
